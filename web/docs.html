Documentation

FŁY takes a Lua or Luau script and returns a protected version of it. There's nothing to install — paste code into the obfuscator or call the API directly.

Quickstart

  1. Open the obfuscator.
  2. Paste your script into input.lua.
  3. Choose a mode — 2 VM is the default and the one most people want.
  4. Click Protect. The result appears in output.lua on the right.
  5. Click Copy and use the output exactly like your original file — it's still plain Luau.
Protected output is a drop-in replacement for your original script. Nothing about how you run or require it changes.

Modes

Every script goes through the same four pipeline stages; the mode changes how they're assembled.

ModeShapeWhen to use it
1Single interpreterSmaller output, one VM layer. Good for scripts where size matters more than depth of protection.
2Outer + inner (nested)The default. A second VM wraps the first, so a reader has to get through two layers instead of one.
hybridEncrypted payload + loadstringSkips virtualization in favor of a single encrypted payload decoded at runtime — faster to protect, structurally different from modes 1 and 2.

Pipeline stages

Virtualize

Your script is compiled and remapped onto a private instruction set, then run by an interpreter generated for that specific build.

Mutate

The opcode map, local names, and dispatch keys are regenerated per build. Two scripts protected back to back won't share a byte-for-byte structure, even if the source was identical.

Lock constants

String and number literals leave the output encoded rather than as plain text, and are only reconstructed at the point they're used.

Integrity

Before the dispatch loop starts, a payload checksum and a small anti-debug probe run ahead of your script's own logic.

API

The obfuscator page calls a single endpoint — you can call it yourself from a build script or editor plugin instead of using the page.

Request

POST /api/obfuscate
Content-Type: application/json

{
  "code": "print(\"Hello from FLY\")",
  "mode": "2"
}
FieldTypeNotes
codestringRequired. The Lua/Luau source to protect. source is also accepted as a key.
modestringOptional. One of "1", "2", "hybrid". Defaults to "2" if omitted.

Response

{
  "success": true,
  "mode": "2",
  "code": "-- protected source --"
}

On failure, the response is { "success": false, "error": "..." } with a non-200 status.

Limits & errors

  • Missing code — the request needs a non-empty code (or source) field, or the API returns an error immediately.
  • Request size — very large scripts may need to be split or sent via the API rather than pasted, depending on how the obfuscator page's editor handles them.
  • Unknown mode values — anything other than 1, 2, or hybrid falls back to the 2-VM default rather than failing.

FAQ

Does protected output run differently from the original?

No. Every stage is built to preserve behavior — what changes is how the file reads, not what it does when it runs.

Is obfuscation reversible?

No obfuscator makes a script impossible to read with enough effort. FŁY's job is to raise the cost of that effort well past what copying a public script would normally take.

Do I need anything installed to run the output?

No. The result is a plain Luau file — no native binaries, no runtime dependency beyond whatever already runs your Luau scripts.

Which mode should I start with?

Mode 2 (the default) is the right starting point for most scripts. Try hybrid if you want faster turnaround and don't need the nested-VM structure.
